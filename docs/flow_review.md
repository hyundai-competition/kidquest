# PRD와 부모·아이 흐름 대조 (2026-11-06)

검토 기준: 팀이 공유한 KidQuest PRD의 사용 장면, F01~F14, F25, 화면과 음성 절. PRD는 팀 검토 초안이며 부모·아이 사용성 시험의 결과는 아니다.

## 목표 흐름

1. 부모가 정차(P) 중 중앙 화면에서 연령, 이야기 목적지, 음성 인식 동의를 고른다.
2. 앱이 뒷좌석 탑승과 벨트를 자동 확인한다. 아이에게는 음성으로 안내한다.
3. 센서로 확인하기 어려운 카시트 등에서만 부모가 직접 확인한다. 매번 눌러야 하는 다음 버튼이 아니다.
4. 벨트 확인 후 D이면 엔진이 이륙을 판단한다. 아이는 화면 조작 없이 듣고 짧게 답한다.
5. 내비 안내·벨트 해제·부모 끄기에는 멈춘다. 부모 끄기는 직접 다시 켤 때까지 유지한다.
6. 도착 전 P는 정박, 도착 또는 임무 종료 뒤 P는 착륙한다. 정차한 뒤 배지와 결과를 본다.

중앙 디스플레이는 부모의 설정·중단 화면이다. 뒷좌석 디스플레이로 자동 넘기는 흐름은 이번 MVP가 아니다. 전용 화면(F28)은 P2이고, 뒷좌석 전용 소리(F22)는 P1의 가능 여부 시험이다.

## 현재 구현과 차이

| 항목 | 상태 / 다음 작업 |
|---|---|
| 연령·목적지·동의 화면 | 선택과 사건 전달 구현. 연령은 기기에 저장한다 |
| 연령·목적지 이야기 | 엔진 분기는 미구현. 시험 목적지는 개발 데이터이며 실제 목적지 콘텐츠로 교체해야 한다 |
| 자동 탑승·벨트 확인 | SDK 최초 조회와 화면 표시 확인. 콘솔 변경 시험은 남아 있다 |
| 부모 확인 | 선택적인 보조 버튼으로 안내를 바꿨다. 현재 엔진의 확인 범위는 탑승한 좌석 전체라 좌석별 카시트 확인은 별도 약속이 필요하다 |
| 발사 준비 | 엔진에는 READY가 있지만 화면 명령은 CREW_CHECK를 유지한다. 준비 완료 안내를 화면 상태로도 보낼지는 엔진 담당과 맞춘다 |
| 주행 화면 | 주행 규제 수신 시 최소 화면. 실제 기어 D·속도 변경과 규제 타이밍은 콘솔 시험이 필요하다 |
| 아이의 음성 참여 | TTS·효과음·STT·포커스는 로그용 구현이다. 아이가 듣고 반응하는 흐름은 아직 완성되지 않았다 |
| 정박 | 여기서 착륙 구현. PRD의 정박 중 카시트 확인 버튼은 후속 연결이 필요하다 |
| 착륙 | 보상 이름 표시와 다시 하기 구현. 우주선 완성·배경·배지 디자인은 남아 있다 |
| 개발 패널 | 정차 때 접힌 상태로 제공. 사용자용 빌드에서는 개발 화면과 분리해야 한다 |

## 판단

중앙 화면에서 부모가 준비하고 아이가 소리로 참여하는 큰 흐름은 PRD와 일치한다. 현재 연결 시험을 실제 사용자 경험 완성으로 보지는 않는다. 음성 안내와 반복 설정 부담, 카시트 확인의 이해도, 운전자 방해 정도는 부모 인터뷰와 보호자 동반 정차 시험으로 확인해야 한다. PRD에 적힌 주행 중 앱 허용 여부도 이 검토만으로 확정하지 않는다.
