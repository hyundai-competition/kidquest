# 브루미 시작 화면 변경 (2026-11-08)

## 회의 반영

- 앱 표시 이름은 브루미, 화면 워드마크는 Vroomie다. 기존 설치를 갱신하도록 applicationId는 com.kidquest.app을 유지한다.
- 우주선 대신 크림색 종이·초록색 지도·금색 보물상자와 탑 장식을 사용한다. 외부 이미지나 로고를 복사하지 않고 Canvas로 그렸다.
- 시작은 경로 → 테마 → 연령·음성 설정의 세 단계다. 뒤로 이동하거나 창 크기를 바꿔도 ViewModel의 선택값은 유지한다.
- 경로는 서울→경주, 서울→부산, 서울→안동, 대전→서울 네 개다. 기본 선택은 서울→경주이고 선택한 ID를 기존 DestinationSelected로 전달한다. 내비게이션 경로를 설정하는 기능은 아니다.
- 테마 네 개 중 history(역사 보물찾기)만 활성화한다. 다른 세 개는 이름이 정해지지 않아 준비 중 01~03으로 둔다. 비활성 버튼과 ViewModel 양쪽에서 잠금 선택을 막는다.
- 목적지 그림은 경주 첨성대, 부산 바다와 다리, 안동 기와집, 서울 궁궐로 구분한다. 이번 탐험의 단서 영역은 제거했다.
- 탐험을 시작하면 선택한 경로의 출발지와 목적지 도시의 탐험 장소 4곳을 연결한 보드 지도가 메인이 된다. 실제 위치·내비 경로와는 연결하지 않았다. 장소를 누르면 화면 시연 미션을 시작한다.
- 기존 상태 안내와 시연 대사는 우주선·이륙 대신 탐험대·보물·출발 표현으로 바꿨다. 엔진 이벤트와 상태 enum 이름은 연결 호환을 위해 그대로 둔다.

## 이번 범위에 넣지 않은 것

- 장소 설명·음성 및 연령별 체험 미션은 [city_missions.md](city_missions.md)에 정리했다. 기존 창작 음성 에피소드와 장소 체험은 별도 흐름이다.
- 현재 음성 시연은 지역에 무관한 창작 보물 단서 두 개다. 네 지역의 검증된 역사 사실을 제공하는 것으로 표현하지 않는다.
- 지역별 에피소드 분기와 실제 좌표·내비 연동은 데이터/엔진 작업과 함께 연결해야 한다. 선택 ID와 화면 소개는 연결했지만 기존 엔진의 목적지 분기는 여전히 후속 작업이다.
- 중앙 화면에서는 주행 규제 상태에 설정·지도·퀴즈를 숨긴다. 화면 퀴즈가 추가되면 정차 또는 허용된 승객 화면에서만 진행하도록 별도 설계한다.
- 교육 원고는 사용자가 제공한 내용이다. 역사 사실의 외부 출처 검수와 실제 유물 사진 확보는 후속 작업이다.

## 확인 결과

- core/app 단위 시험과 앱·테스트 APK 빌드 통과.
- 실제 Pleos API 34에서 시작 화면 시험 3개 통과: 네 경로 선택, 잠긴 세 테마 선택 불가, 628dp 폭에서 글자 잘림 없음, 1500dp 복귀·Activity 재생성 후 선택 유지, 탐험대 확인 및 출발 연결.
- 첫 전체 기기 시험에서는 시작 버튼 텍스트 측정 잘림 1개를 발견했다. 해당 글자의 폭을 보완한 뒤 관련 화면 시험 3개를 다시 통과했다. 나머지 기존 기기 시험 7개는 전체 실행에서 통과했다.
- 지도 그림과 테마 화면을 캡처해 확인했다. 테스트 앱은 제거하고 실제 앱만 남긴다.

## 장소 화면 배치 보완

- 장소 설명·퍼즐은 앱 영역 전체를 사용하는 불투명 화면이다. 지도는 뒤에 남겨두지 않는다.
- 넓은 창에서는 그림과 설명을 두 열로, 좁은 창에서는 한 열로 배치한다. 돌아가기와 미션 시작은 스크롤 영역 밖에 둔다.
- 모든 도시 일러스트는 800×500의 기준 좌표를 등비율로 확대·축소한다. 장소 소개 영역도 1.6:1을 유지한다.
