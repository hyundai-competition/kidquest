# 11-09 회의·통합 시연 후 화면·음성 검토 (11-10 작업)

이 문서는 첫 검토 시점의 기록이다. 이후 추가한 언어·차량 배경·BGM과 최종 점검 범위는 [최신 연결 설명](weather_music_language.md)을 따른다.

기준 main: cd1fc4c (#58까지). 브랜치 feature/screen-controls. 사용자 요청에 따라 간단한 화면 수정부터 진행하고, 보류·의견 요청은 구현하지 않았다. 커밋·푸시는 승인 전 수행하지 않는다.

## 바로 수정

- #62 종료·뒤로: 모든 화면에 뒤로·끝내기를 제공한다. 설정 단계·놀이터 안에서는 이전 화면으로 돌아간다. 진행 중 본편에서 뒤로를 누르면 처음으로 돌아갈지 묻는다. 끝내기도 한 번 더 묻는다. 취소는 엔진 상태를 바꾸지 않는다.
- 처음으로 확정은 기존 RestartPressed를 쓴다. 엔진이 주행·멈춤·정박에서도 이 사건을 받아 StopAudio 후 START로 돌아가도록 허용했다. 임무·보물·놀이터·동의는 정리하고 실제 기어·탑승·벨트·차 환경값은 유지한다. 가짜 도착이나 보상을 만들지 않는다.
- 앱 종료 확정은 음성·듣기·차량 수집 연결을 종료한 뒤 Activity.finishAndRemoveTask를 호출한다. 프로세스 강제 종료 명령은 쓰지 않는다.
- #63 비활성 답 보기: disabled Material 버튼에 남던 클릭 동작 대신, 클릭 없는 Surface와 명시적인 disabled 버튼 의미·텍스트를 사용한다. 내부 글자도 별도 활성 항목으로 나오지 않게 접근성 트리를 정리했다. 활성화되면 기존 OutlinedButton으로 답을 받는다.
- #68 진단: StopAudio 출처를 KQFlow로 구분한다. 엔진 사건 종류, 화면 요청, 컨트롤러 종료를 구분하며 발화·음성·좌표는 기록하지 않는다. 원본 kq_log.txt가 없으므로 P 대사 끊김 원인을 확정하거나 해결됐다고 표시하지 않는다.

## 첨부 시연 코멘트 반영

- 통합 앱의 콘솔 D에서는 시스템 차단 대신 앱 자체의 간소한 주행 화면이 관측됐다. signalcheck의 결과를 통합 앱에도 자동 적용한다고 쓰지 않는다.
- 주행 중 터치 답을 못 고르고 무응답 안내로 진행하는 것은 현재 주행 화면 정책과 맞는다. 음성의 실제 최종 인식은 별도 실발화 시험이 필요하다.
- 퍼즐의 재생 모드 패널은 추가하지 않았다. P 전용 퍼즐이 D에서 닫히는 실제 검증에는 콘솔을 쓴다.
- 탑승 확인에서 부모 확인이 필요했던 것은 안전 조건을 우회해 제거하지 않았다. #44에서 현재 좌석·벨트 읽기와 카시트 대체 확인을 점검한다.
- 정박 음성 끊김은 원본 로그 없이 추정 수정하지 않았다. 재현 시 `adb logcat -s KQCar KQFlow KidQuestVoice`로 사건과 중단 출처를 함께 수집한다.

## 검증

- core 182개·앱 JVM 37개, 총 219개 단위 테스트 통과. 앱·테스트 APK 빌드 및 저장소 검사 통과.
- Pleos 기기 시험 7개 통과: NavigationControlsTest 3개, GameplayFixesTest 2개, VoiceQuizUiTest 1개, TripScreenTest 1개. 종료 취소·확정, 주행 중 초기화, 비활성 보기, P 전용 퍼즐, 좁은 결과 화면 등을 확인했다.
- 실제 접근성 트리를 순회해 비활성 보기의 clickable=false, enabled=false를 확인했다. 텍스트 검색 API만으로 Compose 가상 노드가 조회되지 않아 트리 순회 방식으로 검증했다.
- 종료 확인창 캡처를 확인했다. 실제 뒷좌석 마이크, 내비 지도 임베드, 실제 날씨 연동을 완료했다고 표현하지 않는다.
