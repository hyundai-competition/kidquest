# 시작 화면 연결 확인

## 작업 기준

- `engine-basic`과 `feature/car-signal-collector`를 로컬에서 통합한 화면 작업이다. 두 선행 브랜치는 main에 합쳐지기 전이다.
- 앱 구조는 팀의 `screen/`, `car/`, `storage/`, `voice/`를 유지한다. `AppViewModel`이 시작 선택과 저장을 맡고 `AppController`가 사건을 엔진에 전달한다.
- 시작 화면은 연령, 목적지, 듣기 동의를 사건으로 보낸다. 현재 엔진은 연령과 목적지 분기를 아직 처리하지 않는다.
- 연령만 `LocalStore`에 저장한다. 듣기 동의와 목적지는 실행 중에만 유지하며, 새 항해에서 듣기 동의를 다시 확인한다.
- 차량 상태 표시는 수집된 최신값이며, 값이 없으면 미확인이다. 화면이 이륙을 직접 판단하지 않는다.
- 음성은 기존 로그용 구현이다. 실제 TTS·STT·오디오 포커스는 이번 변경에 포함하지 않는다.

## 에뮬레이터 시험 순서

1. 차량을 P로 두고 앱을 실행한다. 주행 규제가 켜지면 설정과 재생 패널이 숨겨진다.
2. 연령, 목적지, 동의를 선택하고 `승무원 확인하기`를 누른다.
3. 콘솔에서 뒷좌석 탑승을 바꾸고 표시가 갱신되는지 본다.
4. 벨트 입력이 콘솔에 있으면 바꾼다. 없으면 정차 상태의 재생 모드에서 `벨트 매기`를 사용한다. 재생 입력이 포함되었다는 표시가 나온다.
5. 콘솔에서 D로 바꾼다. 엔진의 `ShowScreen(FLYING)`이 비행 화면으로 연결되는지 본다.
6. 벨트를 풀면 멈춤, 다시 매면 비행으로 돌아가는지 본다.
7. P로 바꾸면 정박한다. `여기서 착륙` 뒤 `다시 하기`를 누르고 탑승·벨트 값이 유지되는지 본다.
8. 이미 탑승·벨트가 입력된 상태에서 시작해도 D 입력으로 이륙하는지 본다.
9. 창 크기를 바꾸어 상태가 유지되는지 본다. 앱을 다시 실행하면 연령은 유지되고 듣기 동의는 꺼진다.

재생 모드로 넣은 값과 실제 SDK에서 읽은 값은 시험 결과에 구분해 적는다. 규제 중에는 재생 패널을 열 수 없으니 콘솔에서 P로 돌아온 뒤 조작한다.

## 남아 있는 팀 연결

- RoadAhead 반복·신호 실패 시 시간 대체·경로 취소 후 ETA 처리는 엔진/차량 담당 협의가 필요하다.
- 현재 엔진은 탑승·벨트·기어를 시작 전에도 받고, RestartPressed에서도 유지한다. 부모 확인은 새 항해마다 다시 필요하다.
- 실제 주행 규제 값이 들어오면 최소 화면만 표시한다. 이미 D인 상태의 설정은 P로 돌아온 후 진행한다.

## 2026-11-06 확인 결과

- 빌드: 설치된 JDK 21로 `:app:assembleDebug`, `:app:assembleDebugAndroidTest` 성공. 팀 Gradle 8.10.2는 JDK 25에서 실행되지 않았다. IDE의 Gradle JDK도 17 또는 21로 맞춘다.
- 단위 시험: `:core:test`, `:app:testDebugUnitTest` 통과. 시작 전 탑승·벨트·D 입력, 재시작 후 상태 유지, 미확인 값 구분을 포함한다.
- Pleos API 34 기기 시험: 시작 버튼과 승무원 화면, 재생 패널 펼침·접힘, 재생 입력으로 비행·벨트 멈춤 확인. 안드로이드 연결 시험 2개 통과.
- 실제 SDK 최초 조회: 기어 P, 뒷좌석 좌·중·우 탑승 true, 벨트 false를 수집했다.
- 비행 전환에는 모든 뒷좌석의 탑승·벨트 true와 기어 D를 **재생 모드**로 넣었다. 실제 콘솔 조작으로 값이 바뀌는 시험은 아직 하지 않았다.
- 창 폭별 분기 코드는 구현했으나, 실제 분할 창 변경 시험은 아직 하지 않았다.
- TTS·STT와 연령·목적지별 이야기 분기는 미구현이며 이번 화면 연결 완료와 구분한다.
